# Решение: дизайн reconcile-миграции PR-0.1 (is_purchasable + safe down)
Статус: ПРИНЯТО (технически решаемо) · 2026-06-25 · Инженер · метод /crucible

## Вопрос и критерий «хорошо»
Как написать reconcile-миграцию Корзины 2, чтобы: **гейт зелёный** (parity-БД) · **прод НЕ рискованнее** (без деструктивного DDL) · минимум прод≠модель · без code-ripple · простота.
Верифицированные факты (Ревьюер, read-only prod biotact_db PG16):
- `is_purchasable` — прод **nullable, default true**; модель `Mapped[bool]` **NOT NULL** + python `default=True`, **без** server_default (`categories/models.py:29`); цепочка миграций — отсутствует.
- `products.images` уже **jsonb** (56 строк, 38 non-null, 0 битого JSON) → каст безопасен; `advantages` (jsonb), `video_url` — на проде есть, в цепочке нет; **2 GIN-индекса** (`idx_products_images_gin`, `idx_products_advantages_gin`) на проде, нет в модели/цепочке.
- `down` c `DROP COLUMN` снесёт **живые** `images`/`advantages` на проде.

## Под-решение 1 — is_purchasable
Кандидаты: **A** модель→прод полностью (nullable+server_default) · **A′** модель += `server_default=text("true")` (остаётся NOT NULL), прод-nullability-gap → в squash · **B** прод→модель (`ALTER SET NOT NULL`+drop default) · **C** не менять модель, reconcile добавляет NOT NULL/no-default.
**Лидер: A′.**
**Steelman:** A′ даёт зелёный гейт (parity: `NOT NULL DEFAULT true` == модель с server_default), **ноль прод-DDL**, **ноль code-ripple** (модель остаётся `bool`, не `bool|None`), и **сужает** gap (добавляет недостающий server_default в модель).
**Red-team (что атаковал):**
- *«A′ оставляет прод nullable ≠ модель NOT NULL → латентный None-в-bool»* → баг **пред-существует** (модель уже NOT NULL, прод уже nullable); A′ не ухудшает, squash чинит. Не фатально для PR-0.1.
- *«B чище — прод==модель сразу?»* → B = `ALTER SET NOT NULL` на проде, **падает при NULL>0**, меняет insert-поведение (drop default) → прод-риск, нарушает «без деструктива». Хуже.
- *«A (nullable модель) честнее?»* → A = code-ripple `bool→bool|None` (mypy/код) ради косметики; A′ проще и безопасно.
- *«А если на проде NULL is_purchasable?»* → на A′ не влияет (гейт на parity, не на проде); важно только для squash — там и проверим `count(*)`.
**Вердикт: A′ ВЫСТОЯЛО.**

## Под-решение 2 — down reconcile-миграции
Кандидаты: симметричный DROP · **no-op документированный** · условный.
**Лидер: no-op документированный** (`def downgrade(): pass` + коммент: «baseline-reconcile: колонки/индексы предшествуют цепочке на проде; down — no-op, чтобы не уничтожить живые данные»).
**Steelman:** симметричный DROP снесёт `products.advantages`/`images`/GIN с **живыми данными** (verified); no-op безопасен, up+down проходят на копии без потери данных, re-up `IF NOT EXISTS` идемпотентен.
**Red-team:** *«no-op нарушает down-реверсит-up?»* → для baseline-reconcile это норма (намеренно не реверсим то, что предшествует цепочке); альтернатива (DROP) деструктивна — однозначно хуже. *«условный drop?»* → надёжно не отличить «кто добавил» → сложность без выгоды.
**Вердикт: no-op ВЫСТОЯЛО.**

## Под-решение 3 — GIN-индексы
Объявить в модели (`Index("idx_products_images_gin", "images", postgresql_using="gin")` и для advantages) → метаданные == прод; reconcile создаёт `CREATE INDEX IF NOT EXISTS` (на проде no-op). Иначе будущий автоген против прода предложит их дропнуть (finding #4).

## Остаточный риск + Tripwire
- **Принято:** прод≠модель по nullability `is_purchasable` (и шире: прод = миграции + ручные правки) остаётся до **squash-follow-up** (Q3). Гейт это НЕ ловит — он проверяет цепочка↔модель на чистой БД, **не прод↔модель** (finding #1).
- **Tripwire:** если решим, что прод ОБЯЗАН ==модель ДО Stage 1 (а не через squash) → нужен отдельный прод-DDL PR (count NULL + backfill + `SET NOT NULL`), это меняет план.
