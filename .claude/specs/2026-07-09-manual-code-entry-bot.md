# Ручной ввод кода в боте — Гейт-1 дизайн-мини

**Дата:** 2026-07-09 · **Статус:** ожидает Гейт-1 (Ревьюер свежим контекстом через Капитана).
**Кресло:** Claude=Инженер. **Тип:** бот-фича (aiogram), дополняет QR-поток альтернативным входом.

## 1. Цель
Клиент не может отсканировать QR (камера не читает) → вводит **тот же код** руками в @BiotactBot и
получает баллы. Код под QR = токен перехода (QR оборачивает его в `?start=qr_<code>`), поэтому новой
генерации/логики кодов не нужно — нужен только **второй вход в тот же поток**.

## 2. Решённые развилки (ратифицированы Капитаном 2026-07-09)
- **Телефон — как есть, не трогаем.** «Сначала телефон» остаётся: первый раз бот просит номер (как в
  QR-потоке), повторный — пропускает. Сервер `/qr/activate` телефон не гейтит (`service.py:343-410`) —
  это НЕ меняем; телефон продолжает собирать бот-UX.
- **Без кнопки-подсказки.** v1 = просто напечатать код и отправить (минимум UI). Инлайн-кнопку «Ввести
  код» не добавляем (можно позже).
- **Активация остаётся в мини-аппе.** Бот = «дверь» (принять код + телефон) → открывает мини-апп с
  `?code=` → там согласие + «Активировать». Не тащим согласие/активацию в бота.

## 3. Поток (что увидит клиент)
1. Открывает @BiotactBot → **Start** (обычный `/start`).
2. Печатает 12-значный код (напр. `PNS6DRSDMQD1`) → **Отправить**.
3. **Первый раз:** бот просит номер (кнопка «Поделиться номером») → тап. *(Повторный — шаг пропущен.)*
4. Бот присылает кнопку **«Открыть и получить кэшбэк»** (WebApp, `?code=<code>`) → тап → мини-апп.
5. Мини-апп: галочка согласия → «Активировать» → экран кэшбэка. **(Существующий экран, не трогаем.)**

Это **зеркало QR-потока** (`cmd_start_qr`), только вход — текст, а не deep-link.

## 4. Затронутые файлы (только бот)
- `packages/bot/bot/handlers/loyalty.py` — новый text-хендлер + приватный фильтр/нормализатор + (реко)
  извлечь общий «хвост» из `cmd_start_qr`.
- `packages/bot/tests/…` — тесты нового пути (red→green).
- **НЕ трогаем:** `auth.py`, `common.py`, `__init__.py` (порядок include уже верный, см. §6), мини-апп,
  `/qr/activate`, `codes.py`, логику телефона, сами коды.

## 5. Дизайн хендлера
- **Триггер — кастомный фильтр `is_loyalty_code(text)`** (не голый `F.text.regexp`), т.к. нужна
  нормализация ДО валидации:
  1. `strip()`, убрать пробелы/дефисы (люди читают код группами);
  2. `upper()`; Crockford-конфузаблы: `O→0`, `I,L→1`;
  3. проверить: ровно `CODE_LENGTH=12` символов, все ∈ `_ALPHABET` (`codes.py:20`).
  Фильтр возвращает bool → хендлер срабатывает ТОЛЬКО на код-образный текст; прочий текст (слова, не-12,
  не-Crockford) **проваливается** в существующий catch-all (`common.py:816`). Нормализованный код
  передаётся в хендлер.
- **`StateFilter(None)` на хендлере — ОБЯЗАТЕЛЬНО** (условие Гейта-1, находка Ревьюера). Регистрация:
  `@router.message(StateFilter(None), is_loyalty_code)`. aiogram проверяет хендлеры в порядке регистрации
  по всей цепочке роутеров; активное FSM-состояние НЕ даёт приоритет — оно лишь условие фильтра.
  `loyalty.router` включён первым → без `StateFilter(None)` этот хендлер перехватил бы код-образный текст
  ДАЖЕ когда юзер в `OrderState`/`AIAssistantState`/`waiting_phone`, угнав сообщение у нужного FSM-шага.
  `StateFilter(None)` = срабатывает только когда активного состояния нет (юзер ничем не занят). Побочно
  снижает риск over-catching 12-буквенных слов до безопасного (ложное срабатывание возможно только вне
  диалога → максимум «получил кнопку мини-аппа на случайный текст»).
- **Dark-gate — В ФИЛЬТРЕ:** `is_loyalty_code` возвращает `False`, если `not settings.loyalty_enabled` →
  код-текст при выключенной программе **проваливается в обычные хендлеры** (catch-all), а не глотается
  молча. (Точнее отражает интент, чем `return` в теле хендлера.)
- **Тело = зеркало `cmd_start_qr` начиная с «есть code»:** `get_or_create` юзера → если
  `phone_verified_at` есть → `_send_activation_launch(message, code, lang)`; иначе state `waiting_phone`
  + `update_data(loyalty_code=code, lang=lang)` + запрос контакта. **Дальше отрабатывает существующий
  `process_loyalty_contact`** (телефон → launch) — его НЕ трогаем.
- **Микро-решение (реко: извлечь):** «хвост» (есть code → phone-ветка/launch) сейчас в `cmd_start_qr`;
  новый хендлер использует ту же логику. Реко — извлечь приватный `_start_activation(message, session,
  state, code, lang)` и звать из обоих (deep-link и text), чтобы phone/FSM-ветка жила в ОДНОМ месте (не
  дублировать load-bearing телефон-логику — дрейф опасен). Альтернатива (дублировать ~6 строк) —
  помечу, Ревьюер решит. Код не логируем (как сейчас).

## 6. Порядок хендлеров: что безопасно, а что требует `StateFilter(None)` (исправлено по Гейту-1)
`__init__.py:12-15` включает роутеры в порядке `loyalty, auth, common`. `loyalty.router` первый →
новый text-хендлер проверяется ПЕРЕД `auth` `F.text.regexp(^[hex]{6}$)` (auth.py:18 — 6 hex, длина ≠ 12,
не пересекается) и ПЕРЕД `common.py:816` catch-all `F.text`. Это безопасно: код-образный текст ловит
loyalty первым, не-коды проваливаются в catch-all.
**ОДНАКО (правка находки Ревьюера):** FSM-хендлеры `common.py:614/646/738` (`OrderState.*`,
`AIAssistantState.chatting`, `F.text` со state) НЕ имеют приоритета за счёт активного состояния — aiogram
идёт по порядку регистрации, а `common` включён ПОСЛЕ `loyalty`. Значит без ограничения новый хендлер
перехватил бы 12-символьный код-текст, набранный ВО ВРЕМЯ заказа/AI-чата, украв его у нужного FSM-шага
(правдоподобно: короткий промо-код, номер, англ. фраза из 12 символов без U). **Фикс = `StateFilter(None)`
на новом хендлере** (§5): он срабатывает только при отсутствии активного состояния, поэтому во время
`OrderState`/`AIAssistantState`/`waiting_phone` сообщение штатно доходит до своего state-хендлера.

## 7. Крайние случаи
- **Неверный/выдуманный код** (12 символов, но не наш): бот проведёт до мини-аппа, `/qr/activate`
  вернёт 404 → мини-апп покажет «код недействителен» (уже реализовано, PR-B). Отдельный бот-ответ не нужен.
- **Уже активированный код:** мини-апп покажет replay «код уже активирован» (существующее ветвление по
  `status`). Не трогаем.
- **Нижний регистр / `O` вместо `0`, `I/L` вместо `1`, пробелы/дефисы:** нормализуются в фильтре (§5).
- **Повторный клиент (телефон есть):** шаг телефона пропускается → сразу кнопка мини-аппа.
- **Текст не код-образный:** фильтр не срабатывает → существующее поведение (catch-all), ничего не ломаем.
- **Флаг off:** dark-gate → ничего.

## 8. Тест-план (pytest, aiogram-моки; правило №0 red→green)
- [ ] Код-образный текст (валидный Crockford-12) + телефон не верифицирован → бот просит контакт,
      `loyalty_code` в FSM. Мутация: сломать фильтр → тест краснеет.
- [ ] Код + телефон верифицирован → сразу `_send_activation_launch` (кнопка мини-аппа с `?code=`).
- [ ] **Нормализация:** нижний регистр / `O`→`0` / `I,L`→`1` / пробелы-дефисы → тот же код на выходе.
- [ ] **Фильтр отсекает не-коды:** обычное слово / 6-hex (админ-код) / короткая строка → хендлер НЕ
      срабатывает (проваливается дальше). 6-hex не перехватывается loyalty (не 12-Crockford).
- [ ] **`StateFilter(None)` (условие Гейта-1):** код-образный текст ВО ВРЕМЯ активного `OrderState`/
      `AIAssistantState` → лоялти-хендлер НЕ срабатывает, сообщение доходит до state-хендлера. Мутация:
      убрать `StateFilter(None)` → тест краснеет (лоялти угоняет сообщение).
- [ ] Dark-gate: `loyalty_enabled=false` → хендлер молчит.
- [ ] Полный локальный CI бота (`ruff check bot/` + `pytest tests/`), вывод в отчёт.

## 9. Definition of Done
- Ручной ввод кода в боте работает как §3; телефон-логика/QR-поток/мини-апп/`activate`/коды не тронуты.
- `ruff` + `pytest` зелёные (вывод приложен), red→green доказан.
- Отчёт → Гейт-2 отдельным Ревьюером свежим контекстом; **`/python-review` обязателен** (Python-diff);
  `/security-review` точечно (фильтр на пользовательский ввод: без ReDoS/инъекций, код не логируется).

## 10. Не в скоупе (v1)
Инлайн-кнопка «Ввести код»; активация прямо в боте (без мини-аппа); изменение телефон-политики; любые
правки мини-аппа/бэкенда/кодов; локализация сверх существующих `TEXTS` (ru/uz — если новый текст, зеркалю оба).
