**Это маяк жизненного цикла процесса БОТА, а не монитор мини-аппа.** Проверено:

| Событие | Придёт ли сообщение | Почему |
|---|---|---|
| плановый рестарт/деплой бота | ✅ 🔴 + 🟢 | вежливая остановка, хук успевает отработать |

| OOM-kill / `kill -9` / паника ядра / нет питания | ❌ ничего | `SIGKILL` не перехватывается, хук остановки не выполняется |
| Postgres лёг / nginx упал / сертификат истёк / диск полон | ❌ ничего | бот про это не знает |
| бот упал и не поднялся | ⚠️ 🔴 без 🟢 | требует заметить **отсутствие** второго сообщения — слабый вид тревоги |

**Внешнего монитора нет** (проверено): в логах nginx за всё время на `/health` ходят только краулеры

**Следствие для предложения:** сторож не дублирует маяк — он закрывает ровно его слепые зоны: проверяет

восстановилось; следит за диском, сертификатом и свежестью бэкапа. Маяк остаётся как есть, его не трогаем.

### 3.1 Проверенные факты про Hermes (по состоянию на 18.08.2026)

Проверено вызовом GitHub API и чтением официальных доков, не по памяти:

- Репозиторий `NousResearch/hermes-agent`: **232 146 звёзд**, 46 254 форка, лицензия **MIT**, язык Python,
  создан 22.07.2025, последний коммит — **сегодня**, релизы почти ежедневные (`v2026.8.16.2` от 17.08).
  Для калибровки популярности: репозиторий `anthropics/claude-code` — 141 798 звёзд. Открытых issue — 32 846.
- Позиционирование: «self-improving AI agent… creates skills from experience, improves them during use».
  Умеет: cron-расписание, спавн субагентов, мессенджеры (Telegram, Discord, Slack, WhatsApp, Signal), TUI.
- Требования: Python 3.11, Node.js, ripgrep, ffmpeg; ставится своим установщиком
  (`curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`). Работает «на $5 VPS».
- Модель — любая: Nous Portal, OpenRouter, OpenAI, собственный эндпоинт (`hermes model`).

**Ответ на вопрос Капитана «можно ли поставить Hermes через Claude CLI как агента»: направление обратное.**
1. Hermes — **самостоятельный рантайм**, а не расширение Claude Code. Внутрь Claude Code «поставить Hermes
   как агента» нельзя: субагенты Claude Code — это markdown-описания ролей для той же модели
   (`.claude/agents/*.md`), а не сторонние процессы.
2. Официальная связка — **обратная**: у Hermes есть штатный навык `autonomous-ai-agents/claude-code`, которым
   Hermes **делегирует работу Claude Code CLI** (тот использует твою собственную авторизацию).
3. Есть **сторонний** плагин `niski84/hermes-claude-cli`, который через `claude-bridge` подставляет подписку
   Claude как провайдера модели для Hermes («no API credits required»). ⚠️ Это сторонняя обвязка поверх
   подписки — **до использования свериться с условиями Anthropic**; я не утверждаю ни легальность, ни обратное.

| Репозиторий | Что это по описанию владельца | Звёзд | Лицензия | Язык | Размер | Открытых issue | Последний push |
|---|---|---|---|---|---|---|---|

| `NVIDIA/nemoclaw-community` | примеры/интеграции (цель PR в проекте AgenSig) | 92 | Apache-2.0 | Python | 4 МБ | 16 | 18.08.2026 |

**Главный факт: «Hermes или NemoClaw» — ложная развилка.** Это разные слои: OpenShell — песочница (Rust),
NemoClaw — слой, который запускает **чужих** агентов (в т.ч. Hermes) внутри неё, Hermes — сам агент.
Правильные вопросы: **(1) какой агент** и **(2) в какой изоляции он живёт**.

**Про форк Hermes.** Лицензия MIT — форкать юридически можно. Инженерно — не рекомендую: 670 МБ кода,
33 тысячи открытых issue, релизы почти ежедневно. Форк ради удаления лишнего означает: мы берём на себя
сопровождение чужой быстро меняющейся кодовой базы и **теряем апстрим-исправления безопасности**, ради
того чтобы получить *меньше*, чем даёт готовый инструмент. Правило: не форкают, чтобы вычесть — пишут
недостающее (у нас это ~30 строк).

**Что на самом деле даёт «современные возможности».** Они приходят от модели и её инструментов, а не от
обвязки. На проде **уже установлен** зрелый агентский рантайм — Claude Code (`/usr/bin/claude` 2.1.76,
авторизован): инструменты, субагенты, MCP, навыки, headless-режим `claude -p`. Минимальный современный
агент для нашей задачи = `claude -p` + cron + файл с ролью + отправка в Telegram. Ноль новых рантаймов,
ноль новых ключей, ноль форков.

**Где NemoClaw становится сильным аргументом — и это стратегический, а не технический довод.** Капитан
ведёт проект **AgenSig**, чья цель — merged PR в `NVIDIA/nemoclaw-community` (blueprint «агент держит
мандат, а не ключ»). Запустить наш еженедельный обзорный агент **внутри NemoClaw/OpenShell на bcv2** —
это dogfooding собственного blueprint'а: мы на живой задаче проверяем платформу, под которую пишем вклад,
и получаем настоящую изоляцию (а не «обещание не трогать прод»). Именно изоляция — реальный апгрейд
безопасности, и он **не зависит** от того, какой агент внутри: Hermes, Claude Code или наш скрипт.

**Рекомендация Инженера по этой развилке:**
1. **Не форкать Hermes.** Ни ради минимализма, ни ради безопасности — цена сопровождения выше выгоды.
2. **Шаг 1 — сторож без ИИ** (§5), от него ничего не меняется.
3. **Шаг 2 — еженедельный обзор через `claude -p` с bcv2, только чтение.** ~30 строк, уже оплачено подпиской.
4. **Шаг 3 (опция, стратегическая) — переселить шаг 2 внутрь NemoClaw/OpenShell на bcv2**, когда захотим
   изоляции и практики по AgenSig. Тогда же можно попробовать Hermes как агента внутри песочницы — его
   cron/мессенджеры/навыки там уместны, а риски ограничены песочницей, а не обещаниями.
- **Контраргумент против себя:** три шага вместо «поставил Hermes и всё». **Не перевесил:** шаг 1 обязан
  быть тупым и всегда работать; шаг 2 стоит ноль и делается за час; шаг 3 — уже про стратегию AgenSig,
  а не про то, чтобы узнать о падении мини-аппа.
- **Цена ошибки:** на каждом шаге нулевая — всё живёт вне прода и удаляется файлом.
- **Что изменит выбор:** если агенту понадобится **действовать** на проде (а не только отчитываться) —
  песочница из «опции» становится обязательной, и путь NemoClaw/OpenShell выходит на первое место.

«сторож без ИИ + `claude -p` только на чтение» покрывает заявленную цель Капитана («минимальный, но

## 3.3 ПЕРЕСМОТР 18.08 после вопроса Капитана «почему bcv2, меня интересует main»

Капитан спросил, почему я вообще указываю bcv2. Перепроверил — **две части моей рекомендации были неверны**,
исправляю до вердикта Ревьюера, чтобы он критиковал актуальную версию.

1. **Инцидент Капитана сторож НА main поймал бы.** Тогда упало приложение, а сервер был жив. Проверка
   `/health` + чтение из БД с самого main ловит этот класс. Вынос на bcv2 добавляет только редкий случай
   «сервер умер целиком» — то есть main закрывает основное, а bcv2 — хвост.
2. **Для агента (работа B) я предлагал bcv2 — и этим сам создавал новую дверь в прод.** Чтобы агент с bcv2
   читал логи/`pm2`/БД, ему нужен SSH-ключ **на main**. Это новый вход на боевой сервер, причём с сервера,
   куда планируется пустить коллегу с его агентами. Ради «безопасности» я предлагал ухудшение.
   На main этот ключ не нужен: `claude` (2.1.76) там уже установлен и авторизован.

**Исправленная раскладка:**

| Что | Где | Почему |
|---|---|---|
| Сторож (проверки + Telegram) | **main**, cron | ловит реальный класс падений; `TELEGRAM_NOTIFICATION_BOT_TOKEN` уже в `.env` — новых секретов не появляется |
| Агент-аналитик (еженедельный обзор) | **main**, `claude -p` по расписанию | уже установлен и оплачен; **не нужен ключ с другого сервера** |
| Копия базы | **bcv2** | единственное, что обязано быть снаружи: бэкап на том же диске — не бэкап (сделано 18.08) |
| (опция, шаг 2) внешний пинг «сервер жив» | внешний бесплатный сервис | закрывает «умер целиком»; не требует ни доступа, ни ключей |

**Безопасность агента на main — контролем прав, а не географией:** роль только на чтение, вывод сообщением
Капитану, любые изменения — через обычный круг с гейтами. Отдельно (уборка, не аргумент): вычистить
`/root/.claude` — 38 МБ транскриптов со старым паролем БД, плюс учётные данные сессии.

**Вопрос Ревьюеру №8:** видишь ли ты причину, по которой сторож всё-таки обязан жить вне main, кроме случая
«сервер умер целиком»? И согласен ли, что ключ bcv2 → main ради агента — это ухудшение, а не улучшение?

### Поправка 1 (снимает БЛОКЕР-1 по факту, принцип оставляем)
Ревьюер: «offsite на bcv2 ещё не настроен, ждёт age-ключа». **Устарело: 1d исполнен сегодня в 06:36.**
Капитан 18.08 отказался от `age`; offsite сделан без шифрования и работает. Доказательство (свежая проба):
```
скрипт: строки 34-42 — блок offsite активен;  /root/.ssh/backup_bcv2 — есть

         06:36 "offsite ok biotact_db-20260818-063618.dump"  ← после
bcv2: -rw------- biotact-backup 246221 biotact_db-20260818-063618.dump
```
⇒ проверка свежести offsite-копии **входит в первый круг**, тревоги-в-пустоту не будет.
**Принцип Ревьюера принят и записан правилом:** сторож не проверяет то, что уже известно сломанным и
ведётся отдельной задачей — иначе рождается слепота к тревогам. Перед добавлением каждой проверки —
убедиться, что она сейчас зелёная.

### Поправка 2 (усиливает БЛОКЕР-2)
Ревьюер: «компрометация bcv2 раньше означала унести нечитаемые зашифрованные архивы». **Уже не так:**
Капитан отказался от `age`, копии лежат **открытым текстом**. Проба: первые байты `PGDMP`,

⇒ БЛОКЕР-2 (не сажать на bcv2 автономного агента) становится **важнее**, чем при написании вердикта.
**Принято: H на bcv2 — только после явного, записанного решения Капитана о расширении периметра, либо на
третьем узком хосте.** До этого H не строится.

   какие часы, потом порог «ноль успешных оплат за N часов в рабочее время». Без замера порог будет либо

## 4. Рекомендация Инженера

**A сейчас (на bcv2) + C через неделю-две. Hermes — как эксперимент на bcv2, но не как сторож и не на проде.**

- **A** закрывает главную боль — «упал, и никто не знает». Сторож живёт **на другом сервере**: с прода он не
  увидел бы собственную смерть. Прод не трогаем ни строкой. Выключается удалением файла.
- **C** даёт то, ради чего Капитан хочет агента: еженедельный обзор «что требует внимания» — сертификаты,
  диск, свежесть бэкапа, новые ошибки в логах, напоминание про окно обновлений. Только чтение; любые
  изменения — обычный круг с гейтами.
- **B отвергаю:** держать учётные данные и транскрипты агента на сервере с платежами — это уже наступило
  (38 МБ, пароль БД внутри); и это ровно тот класс, что породил инцидент: автоматическое изменение на проде.
- **H (Hermes):** сильный кандидат именно для роли C, потому что cron + Telegram + память + навыки уже
  встроены. Но три возражения: (1) «self-improving» и 40+ инструментов = агент, который **действует**, а нам
  в этой роли нужен читатель; (2) ежедневные релизы — движущаяся мишень под боевой задачей; (3) новый рантайм
  и новые ключи. Итог: ставить **на bcv2**, дать доступ к проду **только на чтение**, и сравнить с C по
  результату за пару недель. На прод — нет.

**Сильнейший контраргумент против себя.** Два механизма (сторож + агент) вместо одного «умного» — сложнее в
поддержке, и Hermes честно умеет и то и другое. **Почему не перевесил:** надёжность сторожа обеспечивается
именно его тупостью; объединив, мы ставим факт «сервис жив» в зависимость от языковой модели и внешнего
API. Смерть модели/лимита = молчащий сторож, неотличимый от «всё хорошо».

**Цена ошибки:** нулевая в обе стороны — оба механизма живут вне прода и выключаются удалением файла.
**Что изменит выбор:** нужны графики и история падений за месяц → **D** (Uptime Kuma на bcv2) вместо A;
Капитан хочет один инструмент любой ценой → **H** в роли A+B, но тогда обязателен «сторож сторожа»
(внешний бесплатный пинг), иначе молчание агента неотличимо от тишины.
