# PR-S — Админская авторизация: снять дверь `jwt_router` и ветку `type="access"`

> Дата: 2026-07-27 · Кресло: КОМАНДА (Claude=Инженер + отдельный Ревьюер) · Гейт-1: **редакция 2**
> Редакция 1 получила BLOCKED (снос модели ломал `Migration parity`). Приоритет выше PR-5.3.

## Goal

Закрыть путь, которым посторонний получает токен, проходящий проверку на 18 админских эндпоинтах.
`verify_admin_jwt` принимает пользовательский токен `type="access"` без обращения к БД и без
проверки роли; выдаёт такие токены `POST /auth/login` из контура `jwt_router`, вход в который
открыт публичной саморегистрацией. После PR админскую поверхность открывает только админский
токен, а контур входа перестаёт существовать как маршрут.

## Замер (шаг 0) — выполнен Капитаном, передан Ревьюером

- **Q1 периметр: ОТКРЫТ** → затычка на nginx до PR (ниже).
- **Q2 `admin_users`: один аккаунт, спит с января** — чужих строк нет.
- **Q3 сторонний трафик к контуру: ноль.**

**Что из этого следует (обоснование теперь выводится из чисел, а не из «она и есть дыра»):**
`ACCESS_TOKEN_EXPIRE_MINUTES = 30` (`jwt_router.py:21`), `REFRESH_TOKEN_EXPIRE_DAYS = 7` (`:22`).
Живой `access`-токен мог бы существовать только у того, кто логинился ≤30 минут назад, а новый
можно было бы отчеканить через `/auth/refresh` только по refresh-токену возрастом ≤7 дней. При
нулевом трафике и аккаунте, спящем с января, ни того, ни другого не существует → **снятие ветки
`type="access"` безопасно доказуемо**. Исход «миграция клиента» из редакции 1 отпадает: клиента нет.

## Approach — chosen + why

**Снять ДВЕРЬ, модель оставить.** Удаляем маршруты и ветку авторизации; ORM-класс `AdminUser`,
его запись в реестре моделей и таблицу `admin_users` не трогаем.

**Почему именно так — два блокера редакции 1, оба проверены мной по коду:**

1. **Снос модели уронил бы `Migration parity`.** CI (`.github/workflows/ci.yml`) гоняет
   `alembic upgrade head` → `alembic check` → round-trip → `alembic check` на чистой БД.
   `include_object` (`alembic/env.py:38-50`) исключает ровно `_REF_TABLES = {referrers,
   referral_invites}` — `admin_users` там НЕТ. Убери модель из метаданных, оставив таблицу в
   миграциях, и автогенерация предложит `DROP TABLE` → `alembic check` красный → CI не пройдёт.
   Утверждение редакции 1 «миграций нет, `Running upgrade` быть не должно» держится только
   потому, что модель остаётся.
2. **`src/models_registry.py` импортирует `src.auth.models`** в жёстко зафиксированном порядке.
   В файле висит комментарий о пред-существующем цикле `src.users.router ↔ src.auth.dependencies`,
   который резолвится, только если `src.auth.*` грузится ПОСЛЕ `src.users`/`src.categories`.
   Правка реестра не механическая; удаление модуля без неё — `ImportError` на старте приложения.

**Класс ORM без роутера дверью не является:** обслуживать запросы нечем. Дыра закрыта, гейт
паритета зелёный, данные целы.

**Сильнейший контраргумент:** остаётся мёртвый код (модель + таблица), который через год кто-то
примет за живой контур и «починит» вход. Не перевесил: цена — комментарий в модели с датой и
причиной; альтернатива — красный CI и риск ImportError на старте прода.

**Цена ошибки:** если снос двери что-то ломает — реверт-коммит возвращает маршруты; данные не
затронуты ни в одном сценарии.

**Факт-переключатель:** появится реальный клиент контура → возвращаем маршруты отдельным PR
(модель и таблица на месте, восстановление дешёвое).

## Что установлено кодом (несущие факты, проверены в этом раунде)

1. `verify_admin_jwt` (`dependencies.py:64-80`) принимает `type="admin"`/`secret_key` И
   `type="access"`/`jwt_secret`; возвращает `int(sub)` **без БД**, без проверки существования
   пользователя и без проверки роли.
2. Защищает **18 эндпоинтов в 6 роутерах**: `orders/admin_router` (3), `products/router` (4),
   `banners/router` (4), `categories/router` (3), `uploads/router` (3), `orders/router` (1).
3. Токен `type="access"` выдаёт `POST /auth/login` (`jwt_router.py:162`); вход открыт публичным
   `POST /auth/register` (`:135`, `is_active` по умолчанию `True`) + `GET /auth/verify-email`
   (`:216`), который ставит `is_verified=True` предъявителю токена из собственного письма.
4. **Админка использует другую ветку:** `admin-panel-v2/.../endpoints.ts:4` → `/admin/auth/login`
   → `create_admin_token` (`admin_router.py:176`) → `type="admin"`, подпись `secret_key`.
5. **`AdminUser` (`auth/models.py`) не имеет колонки `is_admin`** — роль живёт на телеграм-модели
   `User`. ⚠️ Ловушка имён: `dependencies.py:85` объявляет `AdminUser = Annotated[User, …]` —
   тип-алиас с тем же именем про другую сущность. На ней я уже ошибся в первом анализе.
6. **`settings.jwt_algorithm` обслуживает и выживающую ветку:** `dependencies.py:74` декодирует
   обе пары цикла по `jwt_algorithm` (`config.py:63`), а подписывает админский токен
   `settings.algorithm` (`config.py:35`, `admin_router.py:187`). Оба сегодня `"HS256"`.
7. **`SettingsConfigDict(extra="ignore")` (`config.py:15`)** — удаление полей из `Settings` при
   живых `JWT_SECRET`/`JWT_ALGORITHM` в прод-`.env` НЕ уронит старт. Проверено специально: это был
   кандидат в мины, мины нет.

## Scope PR

**IN:**
- `src/auth/dependencies.py` — убрать ветку `(jwt_secret, "access")`; оставить только
  `type="admin"`/`secret_key`.
- `src/auth/dependencies.py:74` — **перевести `jwt.decode` на `settings.algorithm`. Обязательный
  шаг, не условие** (факт 6: сегодня декодируем не тем полем, которым подписываем; расхождение
  невидимо только потому, что оба `"HS256"`).
- `src/auth/jwt_router.py` — удалить файл (register, login, refresh, verify-email, me,
  forgot-password, reset-password — пакетом, полуживого контура не оставляем).
- `src/main.py` — снять импорт и монтирование `jwt_auth_router`.
- `src/config.py` — удалить `jwt_secret` и `jwt_algorithm` **после** перевода декода (порядок
  обязателен). Безопасно по факту 7.
- Тесты: красная проба + отказ постороннему на всех шести роутерах + позитив-контроль.

**ЯВНО OUT (и почему):**
- **`src/auth/models.py` (модель `AdminUser`) и `src/models_registry.py`** — блокеры 1 и 2.
  Добавляю в модель комментарий-надгробие: маршрутов нет с 2026-07-27, класс жив ради паритета
  миграций, вход не восстанавливать не подумав.
  ⚠️ **Не путать:** `src/auth/__init__.py:3` экспортирует `AdminUser` **из `dependencies`** — это
  тип-алиас `Annotated[User, Depends(get_current_admin)]`, а НЕ модель. Этот экспорт данным PR не
  затрагивается вовсе. После удаления `jwt_router.py` модель останется импортирована ровно из
  одного места — `models_registry`, — и именно это держит таблицу в метаданных.
- **Таблица `admin_users` и её строки** — решение по данным, не по коду. Один спящий аккаунт;
  оставить/деактивировать/снести — Капитана, отдельно.
- **`ADMIN_CREDENTIALS` сравнивает пароль открытым текстом** (`admin_router.py:465`) — другой
  контур, в бэклог.
- **Ротация `jwt_secret`** — инструмент ветки «инцидент»; по замеру Q2/Q3 инцидента нет.
- **Отзыв доступа / поход в БД в `verify_admin_jwt`** — Open Q4, отдельным решением.

## Acceptance criteria

- [ ] Токен `type="access"` получает **401** на админском эндпоинте (сегодня — проходит).
- [ ] Админский токен `type="admin"` проходит на всех шести роутерах (позитив-контроль).
- [ ] `/api/v1/auth/{register,login,refresh,verify-email,me,forgot-password,reset-password}` → 404.
- [ ] **`alembic check` чист** (гейт `Migration parity` зелёный) — прямое следствие того, что
      модель остаётся; проверяется локально на чистой БД до пуша.
- [ ] Нет ни одного обращения к `settings.jwt_secret`; модель `AdminUser` и запись в
      `models_registry` **на месте** (критерий редакции 1 «нет импортов модели» отменён вместе с
      подходом). Голый `grep AdminUser` для проверки непригоден — тип-алиас совпадёт всегда.
- [ ] Админский токен декодируется тем же алгоритмом, которым подписан (`settings.algorithm`).
- [ ] Вход в админку живьём после деплоя работает (проба Капитана).

удалить `location ^~ /api/v1/auth/ { return 404; }` из ОБОИХ server-блоков (`app.biotact.uz`,
`admin.biotact.uz`), `nginx -t && systemctl reload nginx`, и проверить теми же тремя curl'ами:
`/api/v1/auth/login` → 404 (теперь его отдаёт сам FastAPI, маршрута нет) · `/api/v1/admin/auth/login`
→ НЕ 404 · `/api/v1/products` → 200.
Причина: после сноса маршрутов блок становится пустышкой, а правило на периметре без живой причины
переживёт память о том, зачем оно появилось.

## Немедленное действие Капитана (вне PR)

Периметр открыт; затычка на nginx быстрее любого PR и не требует деплоя приложения:

```nginx
location ^~ /api/v1/auth/ { return 404; }
```

**Границу проверил сам, чтобы не выключить админку:** `jwt_router` объявлен как
`APIRouter(prefix="/auth")` (`jwt_router.py:17`), рабочий админский вход —
`APIRouter(prefix="/admin/auth")` (`admin_router.py:18`); оба монтируются под общим
`api_v1_prefix`, полные пути `/api/v1/auth/*` и `/api/v1/admin/auth/*` не пересекаются, и
префиксный `^~` бьёт только по дыре.

⚠️ Это затычка, а не замена PR: ветка `type="access"` остаётся в коде и продолжит пускать любой
токен, подписанный `jwt_secret`, если такой токен где-то появится.
