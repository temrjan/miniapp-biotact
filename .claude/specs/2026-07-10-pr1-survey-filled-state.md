# PR-1: анкета в мини-аппе — «Заполнена ✓» вместо вечной просьбы — Гейт-1 спека

**Дата:** 2026-07-10 · **Режим:** соло (`/solo`), Капитан дал добро на видение 2026-07-10.
**Природа:** UX-фикс поверх существующих данных. **0 миграций, 0 изменений денежного пути, 0 новых endpoint'ов.**
Один PR: `packages/api` (аддитивное расширение ответа) + `packages/frontend` (состояние карточки анкеты).

## 1. Проблема (слова Капитана)

«В мини-аппе в профиле при каждой активации всё равно "просит" рассказать о себе. Если пользователь
один раз оставил анкету и сохранил — не запрашивать снова».

**Корень (код-проверено):** `GET /loyalty/me` не отдаёт поля анкеты → фронт не знает, что анкета
заполнена → `SurveyCard` всегда рендерит пустую форму (это было осознанное решение старой спеки Q4 —
Капитан его пересмотрел). Прод-подтверждение: Тимур (id 3) и Руслан (id 6) заполнили анкету
(gender/age/city в `customer_profile`), мини-апп продолжает просить.

## 2. Решение

### Бэкенд (аддитивно, read-only)

`GET /loyalty/me` дополняется тремя полями анкеты:

- `LoyaltySummary` (dataclass в `service.py`) + `LoyaltySummaryResponse` (`schemas.py`) + маппинг в
  `router.py`: `gender: Gender | None`, `age: int | None`, `city: str | None`.
  **Поля ответа — голые Optional-типы БЕЗ ограничений** (никаких `SurveyAge`/`StringConstraints`):
  ответ отражает БД, а не валидирует ввод; скопированный `ge/le` уронил бы `/me` в 500 на
  out-of-range значении из БД (колонка — plain Integer без CHECK). [check-F1]
  **Новые поля dataclass — БЕЗ дефолтов**: у `get_loyalty_summary` три точки возврата
  (unknown-user / no-profile / member) — mypy принудит явно заполнить каждую. [check-F5]
- `get_loyalty_summary`: SELECT по профилю расширяется колонками `gender, age, city`
  (тот же единственный запрос, без новых обращений к БД).
- Не-участник / неизвестный юзер / участник без анкеты → все три поля `None`.
- Сериализация: `Gender` — StrEnum (`male`/`female`), Pydantic отдаёт value → совпадает с
  фронтовым типом `Gender = 'male' | 'female'`.

**Развилка (решена мной, не голая):** сигнал «заполнена» = *поля анкеты в ответе* (фронт выводит
`filled = хотя бы одно поле != null`), а НЕ отдельный флаг `survey_completed` по событию
`SURVEY_DONE`. Почему: (а) поля всё равно нужны для префилла формы «Изменить»; (б) ноль лишних
запросов (колонки уже в читаемой строке профиля); (в) `submit_survey` требует ≥1 поля и
перезаписывает его → «сохранил хотя бы раз» ⇔ «хотя бы одно поле non-null» — сигналы эквивалентны.
Контраргумент: событие SURVEY_DONE — «каноничный» маркер; не перевесило — это лишний запрос ради
того же ответа. Цена ошибки: мизер, флаг добавляется аддитивно в любой момент.

### Фронтенд (мини-апп)

- `LoyaltySummaryDto` + маппинг `getMe` в `api/loyalty.ts`: + `gender/age/city` (null-able) →
  camelCase поля в `LoyaltySummary` (`types/index.ts`). **Маппинг явно `dto.gender ?? null`**
  (и для age/city): старый API в окне деплоя поля не шлёт → runtime `undefined` вопреки типу DTO;
  `?? null` держит доменный тип честным. [check-F2]
- `LoyaltySection` уже владеет `data` из `useLoyalty` → передаёт поля анкеты пропсами в `SurveyCard`
  (компонент остаётся презентационным, тесты простые).
- `SurveyCard` — два состояния:
  1. **filled && !editing** → компактная строка: «Анкета заполнена ✓» + кнопка «Изменить».
  2. **иначе** → текущая форма; при входе из «Изменить» поля **предзаполнены** текущими значениями.
- После успешного сохранения в режиме правки → возврат в компактное состояние (инвалидация
  `['loyalty','me']` уже есть в `useSurvey` → props обновятся сами; локальный `editing=false`
  по `onSuccess`).
- **Первое заполнение (filled был false):** после save invalidate → refetch → `filled=true` →
  карточка схлопывается в компакт. **Компакт «Заполнена ✓» сам является подтверждением**; между
  успехом мутации и приходом refetch форма с «Спасибо!» видна доли секунды — допустимо, отдельного
  промежуточного состояния не строим. [check-F3]
- i18n: новые ключи в **ОБА** локаля `ru.json` + `uz.json` (`survey.filledTitle`, `survey.editButton`;
  узбекский — по стилю существующих ключей файла).

## 3. Крайние случаи (проговорены)

- **Частичная анкета** (сохранил только город) → считается заполненной: правило Капитана —
  «сохранил один раз → не просим». Остальное дозаполняется через «Изменить».
- **Очистить поле нельзя** (бэкенд не умеет unset — форма шлёт только непустые поля) —
  пред-существующее поведение, в скоуп не входит; «Изменить» только правит/дополняет.
- **Окно деплоя:** новый фронт + старый API → поля `undefined` → маппим в `null` → `filled=false` →
  показывается форма (текущее поведение, деградация мягкая). Старый фронт + новый API → лишние
  поля игнорируются. Порядок деплоя безразличен.
- **Тёмная программа** (404 от `/me`) → `LoyaltySection` вернёт null — не тронуто.
- **Не-участник** → `SurveyCard` не рендерится (member-only) — не тронуто.
