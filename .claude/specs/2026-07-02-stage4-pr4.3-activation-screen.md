## Цель
Дать пользователю, пришедшему из бота по QR (`https://app.biotact.uz/?code=<code>`), экран: **согласие (обязательный чекбокс) → «Активировать» → `POST /loyalty/consent` → `POST /qr/activate` → результат** (кэшбэк/welcome/флип «Друг»), с корректной обработкой тёмного 404 / чужого кода 409 / непрайса 503. Экран тёмный по факту бэкенда (пока флаг off — нейтральное состояние). i18n ru/uz.

## Контекст (проверено чтением кода)

- i18n: `t(key,{params})`, `uz.json` обязан структурно совпадать с `ru.json` (тип `Translations = typeof ru` → tsc ловит рассинхрон).

## Скоуп PR — что входит
- **Новый роут `/activate` + `ActivationPage`** (lazy, как остальные страницы).
- **Редирект входа:** при заходе на `/` с `?code=<code>` → перейти на `/activate?code=<code>` (маленький in-Router компонент/эффект; бот-URL не меняем — он уже на проде). Без `?code=` HomePage работает как обычно.
- **`ActivationPage`:** читает `code` из `useSearchParams`; чекбокс согласия (обязателен, кнопка «Активировать» disabled пока не отмечен); по нажатию — **последовательно** `POST /loyalty/consent {source:'qr'}` → `POST /qr/activate {code}`; результат **ветвится по `ActivateResponse.status`** (две законные 200-ветки, не путать с 409):
  - `status==='activated'` (реальный claim) → «Вы заработали {points_awarded} баллов» + welcome на первой + флип «Друг» (`tier==='biotact_friend'`+`friend_bonus`) + `balance`;
  - `status==='already_activated'` (свой код повторно; `points_awarded` = **исторический** эхо прошлого начисления, `welcome_bonus:0`, новых баллов НЕ начислено) → «Этот код уже активирован ранее» — **без** формулировки «вы заработали сейчас»; показать текущий `balance`/`tier`, не подавать `points_awarded` как свежее начисление.
  После успеха (любая из двух веток) — инвалидировать `['loyalty','me']` (карта/профиль отражают новое состояние). Кнопка «В профиль» / закрыть.
- **API-адаптер** (`loyaltyApi`): `+consent(source)` → `POST /loyalty/consent`; `+activate(code)` → `POST /qr/activate` (snake→camel маппинг ответа).
- **Типы** (`types/index.ts`): `RegistrationSource`, `ConsentResponse`, `ActivationResult` (camelCase) + DTO.
- **Мутации** (хуки `useConsent`/`useActivate` через TanStack `useMutation`, для тестируемости + инвалидация) — или инлайн в странице; выбор в реализации, но логика та же.
- **Обработка ошибок по `ApiError.status`:** 404 (тёмный / эндпоинт недоступен) → нейтральный экран «программа скоро»; 409 (чужой/использованный код) → «код уже активирован»; 503 (непрайс) → «попробуйте позже» (+ретрай); timeout/сеть/прочее → общая ошибка + ретрай.
- **i18n:** секция `activation.*` в `ru.json` **и** `uz.json` (паритет).
- **Тесты:** `ActivationPage.test.tsx` + расширение `loyalty.test.ts`.

## Критерии приёмки — «PR готов, когда…»
- `?code=` на корне уводит на экран активации; без кода — HomePage не сломан.
- Кнопка «Активировать» disabled, пока чекбокс согласия не отмечен.
- Happy-path (`status==='activated'`): consent→activate по порядку; результат рисует кэшбэк (+welcome на первой, +флип «Друг»/`friend_bonus` на 10-й); `['loyalty','me']` инвалидирован.
- **Replay (`status==='already_activated'`): отдельная ветка** — «код уже активирован ранее», БЕЗ «вы заработали {points_awarded}» (цифра историческая, новых баллов нет); НЕ путается с 409 (чужой код).
- Ошибки: 404→нейтрально (тёмный), 409→«код уже активирован другим» / «недействителен», 503→«попробуйте позже»; сеть/timeout→общая ошибка+ретрай. Код **не** светится в UI-тексте/логах.
- i18n ru/uz — обе секции, паритет ключей; `tsc` зелёный.
- Гейты: `npx tsc --noEmit` · `npm run lint` · `npm run test` (vitest) · `npm run build` — все зелёные.

## Тест-план (vitest + RTL)
- **ActivationPage:** (a) рендерит экран при наличии `code`, кнопка disabled без согласия → enabled после чекбокса (`getByRole('checkbox')`/`getByRole('button')`); (b) happy-path `activated` (mock `loyaltyApi.consent`+`activate`) → вызовы по порядку, результат = кэшбэк+welcome; (c) флип «Друг» (`tier:'biotact_friend'`,`friend_bonus:5000`) → friend-состояние; (d) **`already_activated` → «код уже активирован ранее», БЕЗ «заработали {points}»** (отдельно от 409); (e) 409→«код недействителен/чужой», (f) 503→«попробуйте позже», (g) 404→нейтрально; (h) успех → `invalidateQueries(['loyalty','me'])` вызван.
- **loyalty.ts адаптер:** `consent('qr')`→POST `/loyalty/consent {source:'qr'}`; `activate(code)`→POST `/qr/activate {code}` + snake→camel; проброс `ApiError.status`.
- Денежно-соседний фронт (consent+activate) → **`/review` (fleet)** на Гейт-2 (по стандарту стадии §Тест-план: 4.2/4.3 — review fleet).

## Ключевые решения / вопросы Гейта-1
1. **Точка входа = редирект `/?code=` → `/activate` (реко)** vs рендер активации прямо в HomePage. Реко — отдельный роут: HomePage чистый, страница тестируемая, бот-URL (корень, уже на проде) не трогаем. In-Router компонент читает `useSearchParams` и `<Navigate>`-ит. **← главное решение на подтверждение.**
2. **Результат** рисуем из `ActivateResponse` (есть tier/points/welcome/friend_bonus/balance) + инвалидация `['loyalty','me']`; **не** дублируем LoyaltyCard-логику. Можно опционально показать `<LoyaltyCard/>` на экране результата (она сама подтянет свежий `/me`).
3. **`source` фиксирован `'qr'`** (этот экран — только путь с кодом; `direct` — PR-4.4a).
4. **Consent не хардблокирует** (бэкенд PR-4.2): даже если consent вернул неожиданное — на 404 идём в нейтраль; happy-path строго consent→activate.
5. Скиллы ДО кода: **`/typescript` + `/codex`** (react.md + testing.md).
