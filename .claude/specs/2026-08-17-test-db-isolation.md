# Изоляция тестовой БД между сессиями Инженера и Ревьюера

> Дата: 2026-08-17 · Статус: **ОТЛОЖЕНО решением Капитана («в другой раз»)** — документ на будущее.
> Кресло на момент написания: Инженер. Ничего из описанного не выполнено. Прод не затронут.

## 1. Зачем — что случилось 17.08

Инженер и Ревьюер — две сессии на одной машине, **в одном рабочем каталоге** `~/Dev/projects/miniapp-biotact`
и с **одной тестовой базой** `biotact_test_db` (контейнер `biotact-test-pg`, порт 5432).

Фикстура `tests/conftest.py::test_db` на **каждый тест** делает `Base.metadata.create_all` и после —
`drop_all` (`conftest.py:59,65`). Прогон тестов — это не чтение, это запись в базу: два одновременных
`pytest` сносят таблицы друг у друга.

**Факты дня (оба зафиксированы независимо):**

| Кто | Прогон | Результат |
|---|---|---|
| Инженер | `pytest tests/` в одиночестве | **539/539** |
| Инженер | тот же прогон во время прогона Ревьюера | 16 failed / 28 errors; повтор — ещё хуже; ошибки вида `duplicate key … pg_type_typname_nsp_index (orderstatus)` и `relation "lottery_tickets" does not exist` |
| Ревьюер | первый прогон | 48 failed / 94 errors (число таблиц прыгало 20 → 0 между двумя запросами подряд) |
| Ревьюер | второй | 1 failed / 3 errors — остатки первого столкновения |
| Оба | в тишине | **539/539** |

Опасность не в ложном красном (его видно), а в **ложном зелёном**: чужой `drop_all` может убрать строку,
на конфликте с которой тест обязан был упасть. Ложный зелёный на ядре честности розыгрыша — то, чего
не должно быть.

**Второй, меньший факт:** Ревьюер делал `git checkout` веток в рабочем каталоге Инженера. При
незакоммиченном диффе это потеря работы; 17.08 обошлось, потому что всё было закоммичено.

«Ревьюер только читает» верно для кода, но не для базы и не для рабочего дерева.

## 2. Что мешает простым решениям

- **Очередь через Капитана.** Работает, пока никто не забыл; сегодня забыли (полный прогон идёт 3+ мин,
  оба стартовали «пока тихо»).
- **Переменная окружения в команде** (`DATABASE_URL=… pytest`). Обе сессии — один пользователь и один
  shell-профиль: глобальный `export` попадёт в обе сессии; значит переменную надо ставить в **каждую**
  команду; одна забытая — тихий возврат на общую базу.
- **Имя базы захардкожено в 26 файлах** (`conftest.py` + 25 тестов):
  `TEST_DATABASE_URL = settings.database_url.rsplit("/", 1)[0] + "/biotact_test_db"` — берётся
  **хост:порт** из `DATABASE_URL`, а имя приписывается. Поэтому «другая база тем же именем на другом
  сервере» переключается одной строкой окружения, а «другое имя базы» — нет.

## 3. Два пути

### Путь A · Ops, без кода — второй Postgres + своя рабочая копия у Ревьюера (рекомендация на сегодня)

Изоляция становится свойством **каталога**: Ревьюер заходит в свою копию — автоматически на своём сервере,
без переменных в командах.

Предпосылки проверены 17.08: `biotact-test-pg` = `docker.io/library/postgres:17`, `POSTGRES_USER=biotact`,
`POSTGRES_DB=biotact_test_db`, порт 5432; порт **5433 свободен**; `packages/api/.env` в `.gitignore`;
pydantic-settings читает `.env` из текущего каталога (`src/config.py:12-14`), переменная окружения его
перебивает (проверено эмпирически); тесты импортируют из `src.database` только `Base`/`get_db`, движок
приложения напрямую не используют — поведение тестов не меняется.

**Шаг 1 · второй контейнер** (пароль берётся из `.env`, в чат/документ не попадает):
```bash
cd ~/Dev/projects/miniapp-biotact
podman run -d --name biotact-test-pg-2 -p 5433:5432 \
  -e POSTGRES_USER=biotact \
  -e POSTGRES_PASSWORD="$(grep '^DATABASE_URL' packages/api/.env | sed -E 's#.*://[^:]+:([^@]+)@.*#\1#')" \
  -e POSTGRES_DB=biotact_test_db \
  docker.io/library/postgres:17
podman ps --format '{{.Names}} {{.Status}} {{.Ports}}' | grep biotact-test-pg   # ждём две строки: 5432 и 5433
```
После перезагрузки машины: `podman start biotact-test-pg biotact-test-pg-2`.

**Шаг 2 · рабочая копия Ревьюера** (git worktree; venv переиспользуется, node-зависимости — по разу):
```bash
cd ~/Dev/projects/miniapp-biotact
git worktree add ../miniapp-biotact-review main
sed 's#@localhost:5432/#@localhost:5433/#' packages/api/.env > ../miniapp-biotact-review/packages/api/.env
ln -s ~/Dev/projects/miniapp-biotact/packages/api/.venv ../miniapp-biotact-review/packages/api/.venv
(cd ../miniapp-biotact-review/admin-panel-v2 && npm ci)
(cd ../miniapp-biotact-review/packages/frontend && npm ci)
```

**Шаг 3 · проверка, что Ревьюер на своей базе:**
```bash
cd ~/Dev/projects/miniapp-biotact-review/packages/api
.venv/bin/python -c "from src.config import settings; print(settings.database_url.split('@')[1])"
# ожидание: localhost:5433/biotact_dev
.venv/bin/python -m pytest tests/test_lottery_export.py -q --no-header
```

**Шаг 4 · правило Ревьюеру:** «Работаешь только в `~/Dev/projects/miniapp-biotact-review`: там
`git fetch origin && git checkout <ветка>`, там же гоняешь гейты. В `~/Dev/projects/miniapp-biotact` — не
заходить и ничего не переключать».

**Единственная точка отказа:** прогон из чужого каталога → снова 5432. Отсюда шаг 4.
**Откат:** `podman rm -f biotact-test-pg-2 && git worktree remove ../miniapp-biotact-review --force`.

### Путь B · В коде — база на каждый прогон (надёжнее, дороже; на будущее)

Стандартный приём (так делает pytest-django): сессионная фикстура в `conftest.py` создаёт
`biotact_test_<pid>` в начале прогона (`CREATE DATABASE`) и удаляет в конце; имя вычисляется само —
ни переменных, ни очереди, ни второго контейнера; работает и при параллельных прогонах в CI.
Предпосылка проверена: роль `biotact` в тест-контейнере — `rolsuper=t, rolcreatedb=t`; в CI тот же
образ и та же роль.
Цена: ~25 строк в `conftest.py` + **26 механических правок** (каждый тест-файл берёт
`TEST_DATABASE_URL` из одного места вместо своей копии константы). Один PR тест-инфры, прод-код не
трогается, обратим. Гейт-1 спека — короткая, по «го».

## 5. Что НЕ делаем

Не ослабляем фикстуру (`drop_all` на каждый тест — это и есть изоляция тестов друг от друга), не вводим
`sleep`/ретраи, не «договариваемся устно» как единственную защиту.
