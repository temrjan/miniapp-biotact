# PR-B — 404 UX: отличить «тёмное» от «код не найден»

## Цель
На живой программе (`loyalty_enabled=true`) юзер, отсканировавший коробку с невалидным/чужого-батча
кодом, получает от `POST /qr/activate` **404** и видит сообщение «Программа лояльности **скоро** будет
доступна» — хотя программа УЖЕ доступна, а недействителен именно код. Причина: фронт мапит любой 404 →
`activation.error.dark`, потому что backend 404 перегружен двумя смыслами (тёмный гейт vs неизвестный код).
Цель PR-B — показывать корректное сообщение «код недействителен» для живого неизвестного кода, **сохранив**
сообщение «скоро» для настоящего тёмного состояния.

## Ключевой факт (почему это решается на фронте без бэкенда)
Мутация активации делает ДВА последовательных вызова (`useActivation.ts`):
```
await loyaltyApi.consent('qr');   // 1
return loyaltyApi.activate(code); // 2
```
- **consent → 404** возможен ТОЛЬКО когда программа тёмная (гейт `require_loyalty_enabled` бьёт до любой
  логики; `record_consent` при живой программе не 404 никогда). Тёмное короткит здесь — activate не вызывается.
- **activate → 404** при живой программе = **неизвестный код** (`NotFoundException("Code not found")`).
  Тёмное сюда не доходит (consent упал бы первым).

⇒ «тёмное» и «код не найден» уже различимы на фронте по тому, **какой вызов дал 404** — без изменения
backend-контракта и без компрометации непробиваемости тёмного гейта (гейт остаётся голым 404; фронтовое
сообщение на пробиваемость не влияет — атакующий бьёт по HTTP напрямую, не через наш React).

## Выбранный подход (Design 1 — фазовый тег)
1. В `useActivation.ts`: обернуть вызов `consent`; при `ApiError.status === 404` бросать выделенный
   `ProgramDarkError` (обёртка над исходным ApiError). Остальные ошибки consent и все ошибки activate —
   пробрасывать как есть.
2. В `ActivationPage.tsx`:
   - если `activation.error instanceof ProgramDarkError` → сообщение `activation.error.dark`, без ретрая;
   - иначе — как сейчас через `errorContent(status)`, но **404 теперь → `activation.error.invalidCode`**
     (живой неизвестный код), 409 → `invalidCode`, 503 → `unavailable`, прочее → generic+retry.
3. `errorContent`: сменить кейс `404` c `dark` на `invalidCode`; обновить комментарий (dark больше не
   выводится через status, а через `ProgramDarkError`).

`ProgramDarkError` живёт в `useActivation.ts` (специфичен для флоу активации) и импортируется страницей.
Типобезопасно, без `any`.

## Скоуп PR
**Входит:**
- `packages/frontend/src/hooks/useActivation.ts` — `ProgramDarkError` + перехват consent-404.
- `packages/frontend/src/pages/ActivationPage.tsx` — ветка `ProgramDarkError` + `errorContent` 404→invalidCode.
- Тесты `ActivationPage.test.tsx` — переименовать/уточнить существующий «dark (404)» (consent-404 → «скоро»)
  и ДОБАВИТЬ кейс: consent 200 + activate 404 → «код недействителен», без ретрая.

**ЯВНО не входит:**
- Любые изменения backend (`router.py`/`service.py`/статусы/тело ответа) — контракт не трогаем.
- Отдельное UX «программа на паузе» (реальный `program_paused` сигнал) — это отдельная фича, не этот
  защитный 404.
- i18n-строки уже существуют (`dark`/`invalidCode` в ru/uz) — новые не добавляем.
- Прочие follow-up аудита (PR-C миграции, реордер локов и т.п.).

## Критерии приёмки — «PR готов, когда…»
- Живой неизвестный код (consent 200 → activate 404) → «Код недействителен или уже был использован», без ретрая.
- Тёмная программа (consent 404) → «Программа лояльности скоро будет доступна», без ретрая.
- 409 → invalidCode; 503 → unavailable+retry; сеть/timeout/401/5xx → generic+retry (без регрессий).
- Backend не изменён.

## Развилка для Капитана (Гейт-1)
**Рекомендую Design 1** (фазовый тег, выше): точно различает тёмное/ненайденное, сохраняет обе UX,
0 изменений backend, 0 влияния на безопасность.
- **Самоатака:** добавляет маленький класс ошибки + try/catch в хук + ветку на странице — чуть больше
  кода, чем «слепой ремап». Но именно это и просил Капитан («отличить тёмное от ненайденного»); альтернатива
  теряет UX.
- **Альтернатива (Design 2, дешевле):** просто `errorContent` 404→invalidCode и убрать dark целиком.
  Одна строка, но сообщение «скоро» пропадает — тёмная программа покажет «код недействителен». Приемлемо
  ТОЛЬКО если решим, что «скоро»-экран не нужен (тёмный путь и так почти недостижим живым юзером).
- **Цена ошибки:** мала и обратима в 1 строку в обе стороны.
- **Факт-переключатель на Design 2:** если Капитан скажет «экран „скоро“ не нужен, тёмное = недостижимо» —
  берём Design 2.
