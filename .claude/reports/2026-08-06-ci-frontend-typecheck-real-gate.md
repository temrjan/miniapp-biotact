## Как тестировал — красная фаза В САМОМ CI, не локально

Локальный прогон доказывает команду, но не гейт. Поэтому доказательство снято одноразовой веткой
`test/ci-typecheck-probe` (PR #119, закрыт без мержа, ветка удалена) — одна и та же намеренная
ошибка типов, один и тот же раннер, разница только в команде шага:

**Замер 1 — старая команда `npx tsc --noEmit`** (файл-зонд `const CI_TYPECHECK_PROBE: number[] =
['не число']`):

```
success  Type check     ← ДЕФЕКТ: шаг прошёл при явной ошибке типов
success  Lint
success  Test
failure  Build          ← поймал только Build, шагом позже
```

**Замер 2 — новая команда `npx tsc -b`, та же ошибка, тот же зонд:**

```
failure  Type check     ← ##[error]src/__ci_typecheck_probe.ts(3,46):
                          error TS2322: Type 'string' is not assignable to type 'number'.
skipped  Lint
skipped  Test
skipped  Build
```

Побочно замер 1 подтвердил в реальном CI и второе утверждение спеки: сегодня типы защищает
**только** шаг `Build`.

**Зелёная фаза (локально, точной командой CI):** `cd packages/frontend && npx tsc -b` → `exit=0`.
Плюс замер перед стартом: `npx tsc -b --force` на `main` → фронт `exit=0`, админка `exit=0` —
включение гейта не вскрывает существующий долг. **Зелёную фазу в самом CI даст прогон на PR**
(на ветку без PR этот CI не запускается: `on: push` только для `main`).

`.github/workflows/ci.yml` разобран `yaml.safe_load` — файл валиден, пять джоб на месте.

## Замечено, не трогаю — вне скоупа

1. **Мерж этого PR перезапустит прод.** `ci.yml` не входит в `paths-ignore` шага CI, поэтому пуш
   в `main` заведёт CI → а его успех заведёт `Deploy`. Изменение чисто конфигурационное, но
   выкатка будет настоящая: пересборка фронта и админки, `pm2 restart api bot`, health-check.
   Решение о моменте — Капитана.
2. **`Build` теперь частично дублирует `Type check`** (обе делают `tsc -b`; второй прогон
   инкрементальный и дешёвый). Убирать `tsc -b` из `Build` **не предлагаю** — именно на такой
   «оптимизации» дыра и стала бы боевой.
3. **Ветка `docs/tickets-model-separation`** — содержательно пуста, опережает origin на 2 коммита.
   Кандидат на удаление, отдельным решением.

## Вопросы Ревьюеру

1. **Достаточно ли доказательства?** Красная фаза снята в CI, зелёная — пока локально; зелёная в
   CI появится только после того, как ты скажешь «чисто» и я открою PR. Если считаешь, что порядок
   должен быть иным — скажи, переиграю.
2. **`npx tsc -b` без `--force`** — согласен ли, что этого достаточно? Мои основания: `.tsbuildinfo`
   лежит в `node_modules/.tmp/` (`tsconfig.app.json:3`), а `npm ci` создаёт `node_modules` заново;
   плюс проверено локально, что `tsc -b` ловит новую ошибку даже при существующем кэше сборки.
