# PR-5.1 — Схема розыгрыша + поле 18+ (Этап 5) · отчёт Инженера

Ветка: `feat/stage5-pr5.1-lottery-schema` (`10308e3`) · Спека: `.claude/specs/2026-07-24-stage5-lottery.md`

## Что сделано

Схема-only, тёмное под `loyalty_enabled`, **additive** (существующие колонки не тронуты → откат кода безопасен):

- **`lottery_draws`** (Integer PK, low-volume): `period` `VARCHAR(7)` UNIQUE (месяц YYYY-MM), `prize_label` nullable (маркетинг задаёт), `status` `String(16)` default `open` (open→committed→drawn — String, не PG-enum, как `qr_codes.status`), `total_tickets` default 0, `participant_hash` `VARCHAR(64)` (SHA-256 hex), `hash_published_at`/`committed_at`/`drawn_at`/`created_at` — все `timestamptz`.
- **`lottery_tickets`** (BigInteger PK, high-volume): `draw_id`→`lottery_draws` CASCADE (indexed), `user_id`→`users` CASCADE (indexed), `ticket_number` Integer, `source` `String(16)`, `is_winner` bool default false, `prize_rank` Integer nullable. **`UNIQUE(draw_id, ticket_number)`** — номер = стабильный публичный идентификатор под хешем.
- **`customer_profile.is_adult`** — bool, `server_default false` + NOT NULL (бэкфилл существующих без data-миграции; грандфазер `age>=18` будет в коде PR-5.3, а не тут).

Модели — в `loyalty/models.py` (все Club-таблицы там); подхватываются `models_registry` автоматически (тот же файл). Enum-классы `LotteryDrawStatus`/`LotteryTicketSource` — константы для кода, колонки String.

## Обоснования решений (для ревью)

- **String, не PG-enum** для status/source — паттерн репо для операционных/растущих наборов (`qr_codes.status`, `customer_event.event_type`); заодно нет создания/дропа enum-типа в миграции = безопаснее для деплой-гейта.
- **Оба FK CASCADE** — в отличие от `point_ledger` (RESTRICT, деньги), билеты не деньги и не свидетель учёта: снимок можно удалять с розыгрышем/пользователем.
- **`is_adult` NOT NULL default false** (не nullable) — «18+ подтверждён» это true/не-true; грандфазер через `OR age>=18` в eligibility, поэтому false у старых не исключает их ложно.
- **Время tz-aware** заложено в дизайн (все поля `timestamptz`) — под будущую period-арифметику PR-5.3 (урок jwt_router/PR-6.5-B).
