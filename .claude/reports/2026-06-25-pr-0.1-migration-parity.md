  - 2 broadcasts-индекса объявлены в модели (созданы миграцией 224c920d41d0).
- **CI-джоб `Migration parity`** в `ci.yml` (свой `postgres:17` → `alembic upgrade head` → `alembic check`).

## Как тестировал — команды + вывод (локально, прод НЕ тронут)
- **Паритет (CI-сценарий):** чистая БД → `alembic upgrade head` → `alembic check` = **`No new upgrade operations detected.`**
- **down-safety:** вставил строку в `banners` (1) → `alembic downgrade -1` (no-op down) → `banners` = **1** (данные целы) → `upgrade head` идемпотентно.
- **Идемпотентность на prod-like:** `create_all` из моделей → `alembic stamp e1f2a3b4c5d6` → `upgrade head` (reconcile) = **no-op без ошибок** → `alembic check` **exit 0** (`No new upgrade operations detected.`).

## Отклонения от плана
- Реестр на `importlib`-цикле (а не статические `import` с noqa) — статические dotted side-effect импорты дают непоследовательный F401/RUF100; importlib чище и контролирует порядок.
- Дрейф оказался шире фактов Ревьюера: **целые таблицы `banners`/`settings`** тоже вне цепочки (вскрылось после полного реестра) — reconcile их создаёт.
