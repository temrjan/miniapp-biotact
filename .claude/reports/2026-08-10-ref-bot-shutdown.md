# Остановка и архивация `ref-bot` — исполнено

**Инженер · 2026-08-10.** Опс/инфра по поручению Капитана («останавливай, почисти, архивируй, или
примени способ лучше»). Всё сделанное — **обратимо**; необратимое отложено до отдельного решения.

## Порядок был выбран не тот, что в поручении, и вот почему

Поручение звучало «останавливай, почисти, архивируй». Я исполнил в обратном порядке:
**архив → проверка архива → остановка → уборка.**

Причина: по аудиту исходники бота существовали **в единственном экземпляре** на сервере, без git и
вне файловых бэкапов. Остановить первым — значит на время между шагами держать состояние, где код
уже не работает, а копии ещё нет. Порядок стоил ничего, риск снял целиком.

## 1. Архив — три артефакта, каждый проверен

| Файл (`/root/archives/`) | Что внутри | Назначение |
|---|---|---|
| `ref-bot-full-2026-08-10.tar.gz` | 21 файл + `.env` + слепок версий | **восстановление один-в-один** |
| `ref-bot-code-2026-08-10.tar.gz` | то же **без `.env`** | пригоден для репозитория |
| `ref-bot-requirements-frozen-2026-08-10.txt` | 35 пакетов с точными версиями | см. ниже |

**Полнота доказана сверкой, а не осмотром:** список файлов на диске (21) сверен со списком в
архиве (21), `comm` показал пустое расхождение.

**Восстановимость доказана прогоном:** архив распакован во временный каталог, `md5sum` каждого
файла сверен с оригиналом — `diff` пуст, то есть восстановление даёт побайтово то же самое.

**Вторая копия вне сервера:** оба архива перенесены на машину Капитана в `~/backups/biotact-ref-bot/`,
контрольные суммы после переноса совпали. Полный архив содержит токен и пароль БД, поэтому права
сужены до `600`, каталог — `700`.

## 2. Слепок версий — то, что чуть не потерялось

`requirements.txt` бота задаёт версии **диапазонами** (`aiogram>=3.4,<4`, `sqlalchemy>=2.0` и т.д.).
Удаление `venv` при таких зависимостях уничтожает **точный рабочий набор**: пересборка через полгода
подтянет другие версии, и «восстановить как было» станет невозможно.

Поэтому перед уборкой снят `pip freeze` — 35 пакетов с точными версиями (`aiogram==3.25.0`,
`SQLAlchemy==2.0.46`, `asyncpg==0.31.0`, `httpx==0.28.1`, `pydantic-settings==2.13.0`, `qrcode==8.2`)
и вложен в архив восстановления.

## 3. Остановка

```
pm2 stop ref-bot   → status: stopped
pm2 save           → dump.pm2 обновлён (не воскреснет при перезагрузке сервера)
```

Определение процесса **сохранено** — бот поднимается обратно одной командой `pm2 start ref-bot`,
если окружение вернуть.

**Проверено, что чужое не задето:** `api`, `bot`, `multicard-backend`, `multicard-telegram`,
`csv2txt`, `pm2-logrotate` — все `online`, счётчики перезапусков не сдвинулись; `API /health` → 200.

## 4. Уборка

Удалено только **регенерируемое**: `venv`, `.pytest_cache`, `__pycache__`.
Было 125 МБ → стало **112 КБ**. Освобождено ~125 МБ. Все 21 исходный файл на месте.

## Что я НЕ стал делать — и почему это «способ лучше»

**1. Не тронул базу данных.** В поручении было «почисти», но чистка таблиц `referrers` (60 строк) и
`referral_invites` (3) — плохая идея:
- Данные **уже в бэкапе** (`pg_dump` всей БД ежедневно в 03:00) и занимают байты.
- Таблицы созданы **миграцией основного репозитория** (`8efc0a708641`). Удалить их руками — значит
  развести живую БД с историей миграций; на чистой базе они всё равно будут созданы заново.
- Колонки `users.referral_code` / `orders.referral_code` хранят коды 121 перехода. Снести таблицы,
  оставив колонки, — получить ссылки в никуда.
- Выгода нулевая, риск ненулевой. **Данные — единственный след кампании, и они ничего не стоят.**

**2. Не удалил исходники с сервера.** Архив проверен, но каталог оставлен: 112 КБ ничего не стоят, а
откат остановки должен быть возможен без распаковки. Удалять — отдельным решением, после
«остывания».

**3. Не отзывал токен Telegram и не удалял бота в BotFather.** Это необратимо и отдаёт имя
`@BiotactRefBot` наружу. Решение владельца, не инженера.

## Открытые решения — за Капитаном

**Р-1. Настоящий дом для кода.** Сегодня копии две: сервер и машина Капитана. Обе — на одном столе.
**Рекомендую** завести приватный репозиторий (как у `voice-service`: `github.com/temrjan/voice-service`)
и залить туда `ref-bot-code-*.tar.gz` — тот, что без секретов. *Не сделал сам:* заливка кода на
внешний сервис — публикация, её не делают молча.

**Р-2. Ротировать пароль БД** — он лежит открытым текстом в `backups/backup.sh` и попал в вывод
сессии при аудите. Не зависит от судьбы бота.

**Р-3. Удалить мёртвую `packages/api/src/referrals/`** — 4 файла, ноль импортов, вне git.

**Р-4. Судьба кампании** — из отчёта аудита: хоронить окончательно или оживлять (путь записи
`referral_code` придётся писать заново).

## Как вернуть бота, если решение изменится

```bash

python3.12 -m venv venv
venv/bin/pip install -r /root/archives/ref-bot-requirements-frozen-2026-08-10.txt  # точные версии

```
`.env` на месте, трогать не требуется.
