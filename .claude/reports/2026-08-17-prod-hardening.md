## ✅ Шаг 2 · SSH — вход по паролю закрыт на ОБОИХ серверах, 18.08 (по «го» Капитана)

**Почему bcv2 тоже:** находка Ревьюера 18.08 — на bcv2 `PermitRootLogin yes` + `PasswordAuthentication yes`,
**13 273 попытки подбора за сутки** (на проде 68), и с 06:36 там лежит **незашифрованная** копия клиентской
базы. Капитан: «выключи на обоих серверах, но перепроверь ssh ключи».

**Предполёт — проверка ключей (требование Капитана), до единой правки:**

| | biotact-main | bcv2 |
|---|---|---|
| входов по паролю | **0** за всю историю (journal 90 дн. + все `auth.log*`) | **0** в текущем `auth.log` (15 МБ) |
| входы по ключу | 64 за 7 дней (root) | IP Капитана `192.166.230.11` + прод (перенос бэкапа) |
| ключи root | 7 валидных (+2 битые строки-обрывка — sshd их игнорирует) | 9 валидных (+1 обрывок) |
| люди | учёток нет | `temrjan` ✓ ключ · `ruslan` ✓ ключ |
| права `.ssh` / `authorized_keys` | 700 / 644 — StrictModes проходит | 700 / 600 |

Каждая строка ключа проверена на разбор (`ssh-keygen -l`), а не «на глаз».

**Приём (одинаковый на обоих):** новый файл `/etc/ssh/sshd_config.d/00-hardening.conf` (сортируется первым,
sshd берёт первое значение; существующие `50-`/`60-`/`hardening.conf` не тронуты) →
`PasswordAuthentication no` · `PermitRootLogin prohibit-password` · `KbdInteractiveAuthentication no` →
`sshd -t` → **вооружён автооткат** (`systemd-run --on-active=5min --unit=ssh-guard`: если через 5 минут нет
файла-подтверждения `/root/.ssh_hardening_ok`, сервер сам удаляет правку и перезагружает sshd) →
`systemctl reload ssh` → проверка из **нового** подключения → подтверждение и снятие автооката.

**Доказательства:**
```

  новое подключение → root@vmi3025384 ; permitrootlogin without-password ; passwordauthentication no ; kbdinteractive no
  негативная проба (только пароль) → Permission denied (publickey)
  деплой-ключ github-actions-deploy на месте (grep=1) · канал бэкапа прод→bcv2: dry-run OK
bcv2:          sshd -t OK · reload OK
  новое подключение → root@vmi3020186 ; permitrootlogin without-password ; passwordauthentication no
  люди по ключу: bcv2-temrjan → temrjan ; bcv2-ruslan → ruslan
  негативная проба → Permission denied (publickey)
сквозная проверка ПОСЛЕ закрытия обоих: /usr/local/sbin/biotact-pg-backup.sh → exit=0,
  journal "offsite ok biotact_db-20260818-083609.dump", файл на bcv2 246221 B — канал жив
автооткат снят на обоих (таймеров ssh-guard: 0)
```

**Откат (если понадобится):** `rm /etc/ssh/sshd_config.d/00-hardening.conf && systemctl reload ssh` —
из любой живой сессии, на каждом хосте свой файл. Пароли учёток не менялись, ключи не удалялись,
порт и остальные настройки не тронуты.

**Что это НЕ закрывает:** копия базы на bcv2 по-прежнему **незашифрована** (решение Капитана по `age`).
Дверь по паролю закрыта, но root-доступ по ключу на bcv2 есть у нескольких сторон; экспозиция снижена,
не устранена. Открытый вопрос Капитану: оставить как есть (принятый риск) · зашифровать · перенести на
`netcup-1` (там пароль-вход уже выключен, людей нет).
