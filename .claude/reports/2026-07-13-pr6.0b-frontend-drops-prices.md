# Отчёт: PR-6.0b — Фронт перестаёт слать цены

**Спека:** `.claude/specs/2026-07-13-pr6.0b-frontend-drops-prices.md` (Гейт-1 APPROVED, 0 находок)
**Ветка:** `fix/frontend-drops-prices` · **фронт-only, 0 бэкенда, 0 миграций**

## Сделано — по пунктам спеки

1. `OrderItem` → **`OrderLine`** = `{ product_id, quantity }`. Имя изменено осознанно: «item» с ценой
   и суммой ушёл, осталась строка заказа.
2. `CreateOrderRequest` больше не несёт `subtotal`/`delivery_fee`/`total`, позиция — ни
   `product_price`, ни `total`, ни `product_name`.
3. `buildOrderRequest` — чистая функция, `handlePayment` зовёт её и дальше работает как раньше.
4. `totalAmount` остался — он показывает сумму в UI (`:224`, `:474`); убрана лишь его отправка.
   Из зависимостей `handlePayment` удалён — функция им больше не пользуется.

## Отклонение от спеки — одно, и оно к лучшему

Спека говорила «функция экспортируется из того же файла». **Так нельзя:** eslint дал ошибку
`react-refresh/only-export-components` — экспорт не-компонента из файла страницы ломает fast-refresh.
Глушить правило не стал (rules #10 — чинить причину), вынес билдер в **отдельный модуль**
`src/utils/order.ts` вместе с его типами. Тест переехал туда же (`src/utils/order.test.ts`).
Побочно это и чище: страница снова экспортирует только компонент.

## Как тестировал — команды и вывод

- `npx tsc --noEmit` → чисто
- `npm run lint` → **0 ошибок**
- `npm run test` → **172 passed** (18 файлов; +5 новых)
- `npm run build` → `✓ built`

**Правило №0 — red→green доказан.** Вернул денежные поля в билдер → **2 теста упали**
(«отправляет только товар и количество» и «в позиции НЕТ цены и суммы»), после отката — зелёные.
Защита двухслойная: `tsc` тоже отверг бы лишние поля (excess property check), но тест ловит
**намерение** независимо от типов — проверка идёт по ключам объекта, а не по значениям, поэтому
возврат цены не пройдёт, даже если значение окажется «правильным».

## Замечено, не трогаю — вне скоупа

- **`src/utils/checkout.utils.test.ts` тестирует сам себя:** `validatePhone`/`formatPhoneDisplay`
  объявлены **внутри тест-файла** и там же проверяются — прод-код этот тест не покрывает вообще.
  Это тест-декорация. Отдельная задача (перенести функции в модуль и импортировать), в PR-6.0b не лезу.
- `OrdersPage.tsx` имеет свой локальный `OrderItem` — это тип **чтения** истории заказов, к созданию
  заказа отношения не имеет (подтверждено и Ревьюером на Гейте-1). Не трогаю.

## Поверхность для Ревьюера

(1) **Не сломан ли чекаут** — единственный путь выручки; обязательные поля `product_id`+`quantity`
переписаны мной, и толерантность бэка от ошибки в НИХ не спасает. (2) Вынос билдера в модуль —
отклонение от спеки, прошу подтвердить. (3) `parseInt(item.productId, 10)` — `productId` в сторе
строка (`types/index.ts:49`), в API нужен `int`; поведение то же, что и до PR.
