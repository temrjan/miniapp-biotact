## Сделано — по пунктам спеки (PR-3.1)

1. **Флип статуса под существующим локом.** В `service.py` `activate_code` теперь читает `status` вместе с `lifetime_activations` тем же `SELECT … FOR UPDATE` (один лишний столбец, тот же round-trip). `_accrue` получил `status_before`.
2. **Идемпотентный порог-чек.** `flips_to_friend = status_before == NEWBIE and lifetime_after >= FRIEND_THRESHOLD(10)` — НЕ детект 9→10; робастно к счётчику, уже перешагнувшему 10 (бэкфилл).
3. **Flip-then-accrue по 8%.** `tier`/`rate_bps` вычисляются ДО `get_unit_price`/`compute_cashback`, поэтому 10-я активация начисляется уже по `FRIEND_RATE_BPS=800`.
4. **Бонус +5000 однократно.** При флипе пишется `friend_bonus`-строка (`FRIEND_BONUS_POINTS=5000`, привязана к `qr_code_id`, без price-снапшота) + `customer_event(status_friend, payload={lifetime_activations, bonus})`. Гард `status==newbie` под локом + partial-`UNIQUE(qr_code_id, reason)` → ровно один бонус.
5. **Статус в профиль.** UPDATE профиля пишет `status=tier` (no-op-запись того же значения без флипа; строка уже под локом).
6. **Контракт ответа (МИНОР-1).** `ActivationOutcome` и `ActivateResponse` += `tier` (LoyaltyStatus) и `friend_bonus` (int). `points_awarded = cashback + welcome + friend_bonus`; `welcome_bonus`/`friend_bonus` — разбивка-подполя. Реплей → подполя 0, `points_awarded` = исходный earn кода (вкл. бонус), `tier` = текущий статус. `router.py` маппит новые поля.

**Миграции НЕТ** (enum `loyalty_status` уже с обоими значениями, `reason` — свободный String) → `alembic check` = «No new upgrade operations detected».
